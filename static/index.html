RTT estimation and the timeout interval

TCP must set its retransmission timer longer than the RTT, but RTT keeps changing. It smooths samples with a moving average and adds a safety margin.

EstimatedRTT = (1−α)·EstimatedRTT + α·SampleRTT DevRTT = (1−β)·DevRTT + β·|SampleRTT − EstimatedRTT| TimeoutInterval = EstimatedRTT + 4·DevRTT
Show the table
Timeout too short. A spike above the timer triggers a premature timeout and a useless retransmission. The red markers show where that would happen.
Timeout too long. A lost segment sits unrepeated for the whole interval, so the transfer reacts slowly to real loss. Karn's rule: samples from retransmitted segments are ignored.

Checksum calculator

The Internet checksum: add all 16-bit words, fold the carry back in, flip every bit. The receiver adds everything including the checksum and expects 0xFFFF.

What the assignment is asking

Show, with evidence, how TCP and UDP behave when the network misbehaves. The Week 10 slides give you the theory (sequence numbers, ACKs, RTO, fast retransmit) and the tools (Python sockets, echo client and server).

  • TCP echo and UDP echo programs built from the socket calls on slides 22 to 32
  • Fault injection: loss, ACK loss, delay, duplication, reordering
  • Metrics: delivery rate, order, duplicates, retransmissions, RTT, completion time
  • A written conclusion: when to choose which protocol

Suggested report outline

  1. Goal and setup. Which tests, which parameters, loopback plus the lossy proxy.
  2. Scenarios. Screenshot each tab view: no loss, packet loss, ACK loss, premature timeout, fast retransmit.
  3. Experiment. Loss sweep charts and the copied CSV table.
  4. Real sockets. CLI output from your machine at 0%, 5%, 20% loss.
  5. Conclusion. UDP: lowest latency, no guarantees. TCP: guarantees, paid for in retransmissions and delay.
